# SpinSuite

Dissertation code (MSci Natural Sciences, University of Exeter) for optimal RF control
of radical-pair spin dynamics: disruption of the singlet yield and discrimination
between competing radical-pair hypotheses.

Working rules for this repo are in `CLAUDE.md`.

## Setup

Developed on Windows with Python 3.14.3, NumPy 2.5.1, SciPy 1.17.1, QuTiP 5.2.3,
Matplotlib 3.11.1, pytest 9.1.1.

Run the tests from the repo root:

```
python -m pytest
```

## Units

Settings are given in MHz (couplings, fields, drive frequencies) and µs (times),
with rates in µs⁻¹. Conversion to angular units (rad/µs) happens in one place only:
`angular_frequency()` in `model.py`, which multiplies by 2π. Rates are never
multiplied by 2π. This matches the old repo, where `A_iso`, `J`, `omega_0` and drive
frequencies were all `MHz * 2 * np.pi` and `k_rate` was used as written.

## Where is X?

| Question | Answer |
|---|---|
| Where is the Hamiltonian built? | `static_hamiltonian()` in `model.py` (hyperfine + exchange + electron-electron dipolar + Zeeman, rad/µs). Spin operators: `spin_operators()`, ordered electron 1 ⊗ electron 2 ⊗ nuclei |
| Where is the initial state set? | `electron_initial_state` field of `Hypothesis` (4×4 electron density matrix, nuclei fully mixed); helpers `singlet_density_matrix()`, `triplet_density_matrix()` and `ciss_density_matrix(χ)` (CISS-polarised start, cos(χ/2)|S⟩ + sin(χ/2)|T0⟩, Luo & Hore 2021 eq. 8; CISS axis along the field; electron 1 plays the donor) in `model.py`. Full 12×12 (or larger) state: `initial_density_matrix()` |
| How is CISS (chiral-induced spin selectivity) modelled? | `ciss_density_matrix(χ)` in `model.py`: the pair starts in cos(χ/2)\|S⟩ + sin(χ/2)\|T0⟩ (Luo & Hore, New J. Phys. 23, 043032 (2021), eq. 8), χ = 0 the singlet, χ = π/2 one electron up and one down along the CISS axis. Here the axis lies along the field and electron 1 is the donor. By default only the start changes. The paper's recombination state (eqs. 11-12), cos(χ/2)\|S⟩ − sin(χ/2)\|T0⟩, can be set as `recombination_state` (built 2026-10-15; `flavin_tryptophan_hypothesis` uses it, the baseline CISS runs did not). Checked against the paper's operator form (eq. 10) and the density-matrix reference in `tests/` |
| Where is recombination (Haberkorn) handled? | `recombination_operator()` (K = k_S P_R + k_T (1 − P_R), P_R the recombination projector, the singlet by default) and `effective_hamiltonian()` (H − iK/2) in `model.py` |
| How are Daniel's rates k_r and k_f handled? | Read as K = k_r P_R + k_f × identity (recombination at k_r through the recombination state, spin-independent forward reaction at k_f), i.e. k_S = k_r + k_f and k_T = k_f, set in `flavin_tryptophan_hypothesis` (`model.py`). An assumption to confirm with Daniel. The engine's Y_S counts both channels out of the recombination state; `recombination_yield()` in `engine.py` keeps the k_r share, k_r/k_S × Y_S. Tested against the density-matrix reference |
| Where are Daniel's flavin-tryptophan parameters? | `flavin_tryptophan_hypothesis()` in `model.py`: FN5 on electron 1, WN1 on electron 2 (one nitrogen-14 each), dipolar EED, given by Daniel in rad/µs and divided by 2π once there. Exchange J = 0 (assumption). Dimension 36. Tensor checks in `tests/test_model.py` |
| Where is the electron-electron dipolar coupling? | `dipolar_tensor_MHz` field of `Hypothesis` (S1·D·S2, zero by default), added in `static_hamiltonian()` in `model.py` |
| Where does the Zeeman frequency come from? | For the flavin-tryptophan pair, `zeeman_frequency_MHz(field_strength_uT)` in `model.py`, from SciPy's CODATA electron gyromagnetic ratio (free-electron g): 50 µT gives about 1.40 MHz. The baseline pairs keep DISCO's 28 MHz (may be stale) |
| How is the field pointed in a given direction of the molecule? | `field_direction_hypothesis(hypothesis, θ, φ)` in `model.py`: the field lies along n = (sin θ cos φ, sin θ sin φ, cos θ) in the frame the tensors are given in, and the drive along (cos θ cos φ, cos θ sin φ, −sin θ), perpendicular to the field towards increasing θ (a convention: for a molecule with no symmetry axis the drive's direction around the field matters). `oriented_hypothesis` cannot do this for such a molecule: whatever φ, the field it sees stays in the molecule's xz plane (tested in `tests/test_model.py`) |
| How is the contrast computed? | `recombination_contrast()` in `engine.py`: highest minus lowest recombination yield over a list of field directions (Daniel's primary measure, 9 Oct). As a cost for two pairs under the same drive: `contrast_cost()` in `control.py`, −\|C_A − C_B\| |
| Where is the singlet projector? | `singlet_projector()` in `model.py`. The engine uses `recombination_projector()`, which is the singlet projector unless the hypothesis sets another `recombination_state` |
| Where is the drive operator (which spins the RF field acts on)? | `drive_operator()` in `model.py`: S1x + S2x, along x on both electrons |
| How is a mixed initial state handled? | `initial_kets()` in `engine.py` splits ρ0 into weighted kets; each is evolved separately (exact for Haberkorn) |
| Where is the closed form of the drive exponential? | `drive_exponential()` in `engine.py` (uses X³ = X for X = S1x + S2x) |
| How are yields computed? | `yields()` in `engine.py`: Y_S = k_S ∫ Tr(P_S ρ) dt and Y_T = k_T ∫ Tr(P_T ρ) dt, trapezoid rule on the given time grid. Populations come from `populations()` |
| How is the state propagated under the drive? | `populations()` in `engine.py`: Strang splitting, half drive kick (closed form), full static step exp(−i(H − iK/2)h), half kick; drive sampled mid-step. Error ∝ step² |
| How are two hypotheses simulated under the same drive? | `yields_together()` in `engine.py`: the pairs are stacked as independent blocks of one block-diagonal system (zeros between blocks, so they never interact) and stepped together. `discrimination_cost()` uses it. Tested equal to separate passes to 1e-12 in `tests/test_engine.py` |
| How do I run several searches at once? | `experiments/optimise_drive.py` runs each random seed, `experiments/disruption_sweep.py` each anisotropy and `experiments/null_test.py` each share of the random drives in its own process with `ProcessPoolExecutor` (one BLAS thread each), from the terminal. Results are identical to running one after another (`test_searches_in_separate_processes_match_one_after_another`) |
| How accurate is the engine, and what sets the step? | `yields()` runs at n and 2n substeps (n from `max_step_us`) and combines them as (4 × fine − coarse)/3 (Richardson), error ∝ step⁴. Checked against both references to 1e-6 in `tests/test_engine.py`. n is rounded up, so the actual step can be smaller than `max_step_us`. `optimise_drive.py` uses true 1.5 ns steps (`MAX_STEP_US = 0.00151`): a scratch measurement (2026-10-08) against the density-matrix reference over drives up to 100 MHz gave yield errors at most 1e-5, against 4e-6 at 1.0 ns, and 30% faster |
| Where is the drive normalised? | `control.py`: `linf_drive` (peak equals the cap, as DISCO and APEX did; the peak is checked on times you pass in, the old repo used 0–12 µs with 20000 points) and `l2_drive` (√(Σ a²) equals the cap, fixing average power, as FORGE did) |
| How is a drive described? | `Drive` in `control.py`: frequencies (MHz), amplitudes after the cap (MHz), phases (rad); the drive is Σ a sin(2πft + φ) along x on both electrons |
| Where do drive amplitudes become rad/µs? | `drive_rad_per_us()` in `control.py`, the only place; it gives the function f(t) that `yields()` in `engine.py` takes |
| How are starting frequencies chosen (action-spectrum seeding)? | `action_spectrum()` in `control.py` scores 1 MHz bins by the transitions of the static (Hermitian) Hamiltonian: drive coupling squared × change in singlet character. With `orientations`, every direction's scores are added with its weight before scaling (the spectrum of a sample). `action_spectrum_seeds()` takes the top bins. For discrimination, take `np.maximum` of the two hypotheses' scores first (as DISCO did) |
| How is measurement noise included in discrimination? | Counting noise: N pairs each land in one of three outcomes (singlet product, triplet product, not yet recombined), like coin flips. `bhattacharyya_distance()` in `engine.py` gives B = −ln Σ √(p_A p_B) per pair; after N pairs the chance of picking the wrong hypothesis is at most ½ exp(−N B). `pairs_needed()` turns B into the number of pairs for a chosen error. For small differences B ≈ D² / (8 Y(1 − Y)) with two outcomes |
| How is a drive scored for disruption or discrimination? | `disruption_cost()` (singlet yield, lower is better) and `discrimination_cost()` (minus the gap D, both hypotheses under the same drive) and `bhattacharyya_cost()` (minus √B, the same idea allowing for counting noise; the square root keeps it on a scale like D) in `control.py` |
| Where is the optimiser, and what does one super-iteration do? | `optimise_drive()` in `control.py`: nudge every frequency by a uniform random amount in ±(perturbation), take abs, tune amplitudes and phases by Nelder-Mead (old tolerances xatol 1e-4, fatol 1e-5), keep only if the cost is lower. Stops early after `patience_super_iterations` rounds in a row without improvement (setting it to the number of rounds turns this off, as in the old runs). Random numbers come from a private `np.random.RandomState(seed)`, the same generator as the old code, so old nudges are reproduced exactly |
| What is a hypothesis, and how do I make a variant? | `Hypothesis` in `model.py`; `hypothesis.variant(field=new_value)` returns a changed copy |
| Where are the preset hypotheses? | "Presets" section of `model.py` (`baseline_hypothesis(delta)`: DISCO parameters, may be stale placeholders) |
| Are results averaged over orientations of the molecule? | Optionally, from milestone 8 (2026-10-13): `SEARCH_LEBEDEV_ORDER` and `FINAL_LEBEDEV_ORDER` in `optimise_drive.py` (0 = one orientation). Every run up to `discrimination_2026-10-11_05` is for one orientation: the field along z, which is also the axis of the axial hyperfine tensor (and the CISS axis). The run log says which runs are averaged |
| How are yields averaged over orientations? | Pass a grid from `orientation_grid(order)` as the optional last input `orientations` of `yields_together` / `yields` (`engine.py`), of the three costs and of `action_spectrum` (`control.py`); leave it out for the molecule as given (aligned, as in every run so far). The work is done by `averaged_yields_together()` in `engine.py`: every hypothesis is turned to each direction of `orientation_grid(order)` (SciPy's Lebedev rule: fixed directions with weights summing to 1, so the weighted sum is the average over the sphere) and the yields are summed with the weights. Yields are averaged, then "pairs needed" is worked out once from the averages, as a measurement on a whole sample would. All directions of one hypothesis are stepped together (batched, `orientation_populations`): each step is one NumPy call for every direction. Scratch measurements (2026-10-13): 110 directions (order 17) gives pairs needed within 0.3% of 590 directions; one discrimination evaluation takes 4.0 s with 110 directions and 2.1 s with 50 (one process; one direction at a time took 35 s). Tested in `tests/test_engine.py` against an independent average over tilt, and against the plain one-direction-at-a-time loop `averaged_yields_one_direction_at_a_time` in `tests/reference_engine.py` (agreement 3e-16) |
| How is the molecule turned to another orientation? | (For a molecule with no symmetry axis, such as the flavin-tryptophan pair, use `field_direction_hypothesis` instead, see above; `oriented_hypothesis` and the orientation average are right only for molecules symmetric about their z axis, as every pair before 2026-10-15 was: `IDEAS.md` idea 21.) `oriented_hypothesis(hypothesis, θ, φ)` in `model.py`: the molecule's axis is moved to polar angle θ and azimuth φ (`rotation_matrix`). Hyperfine tensors and the electron start state turn with it (so the CISS axis does too; the singlet is unchanged); the field stays along z and the drive along x. Checked in `tests/test_model.py`: with no field, turning changes nothing; with a field but no drive, spinning about the field changes nothing; the CISS spins point along the turned axis. A tilted pair matches the density-matrix reference in `tests/test_engine.py` |
| Where is the hyperfine anisotropy δ defined? | `axial_hyperfine_tensor_MHz()` in `model.py` |
| Where are MHz converted to angular units? | `angular_frequency()` in `model.py` |
| How do I load a saved run? | `load_run("results/<run ID>.npz")` in `results.py` gives a plain dict of settings and outcome. For old files it renames `number_of_seeds` to `number_of_frequencies` and `..._seeds_MHz` to `..._starting_frequencies_MHz` (listed under `"renamed"`), and for old optimise_drive files fills in settings they did not store (version 1: patience = number of super-iterations; versions 1-2: measure = gap; listed under `"filled_in"`). It never invents results |
| Where are run IDs made and runs saved? | `new_run_id` and `save_run` in `results.py`; both experiment scripts call them in their last cell |
| How do checkpoints and resuming work? | `optimise_drive` (`control.py`) saves a `SearchState` after every super-iteration: best drive, histories, patience count, the random generator's internal state (so the next nudge is the one an uninterrupted run would draw) and time spent. Run-level: `start_or_resume_run` and `finish_run` in `results.py`. Files: `results/checkpoints/<run ID>_unfinished/` (`settings.npz`, `random_seed_<n>.npz`), renamed `_finished` when saved. Tested: a run interrupted part-way and resumed gives exactly the uninterrupted result (`test_interrupted_search_resumes_to_exactly_the_uninterrupted_result`) |
| How are several searches (random seeds) run, and how long does it take? | `run_one_seed` in `experiments/optimise_drive.py`, one process per seed with `ProcessPoolExecutor`, one BLAS thread each. A random seed fixes the nudges (and the start, if random); every seed starts from the same action-spectrum frequencies by default. Scratch measurement (2026-10-08): six processes at once each run about 15% slower than one alone (0.36 s against 0.32 s per discrimination evaluation) |
| How do we know an optimised drive beats luck (null test)? | `experiments/null_test.py`: many random drives at the same strength, scored like the optimised one; reports the fraction that beat it. Random drives drawn by `random_drive_parameters` in `control.py`, all in the main process from one seeded generator, so the set does not depend on the number of processes (checked: 1 and 2 processes give identical yields) |
| Where is one round (super-iteration) of the optimiser? | `one_super_iteration()` in `control.py` |
| How do I see how a round's Nelder-Mead fine-tuning progressed? | Every call's cost is recorded in order (`nelder_mead_costs` in `OptimisationResult`, the checkpoints and optimise_drive.py files from format version 6). Round k's calls are the `evaluations[k - 1]` entries after those of earlier rounds; `np.minimum.accumulate` of them gives the best-so-far curve, which shows what a lower call cap would have lost. Recording changes nothing in the search (tested). Checkpoints from before 2026-10-14 load with NaN there |
| Where are the quick-look plots made? | `save_quick_look` in `results.py` draws them; each experiment script says what goes in them, in its last cell. Report figures come only from `figures.py` |
| Where are the old-repo regression numbers? | Top of `tests/test_reference_engine.py`, each with its source file in the old repo. They come from DISCO and may rely on stale placeholder parameters: sanity checks only |
| Where is the slow reference engine? | `tests/reference_engine.py`. The QuTiP functions are the old engine (k_S = k_T, singlet start, one spin-1 nucleus only); `haberkorn_populations` / `haberkorn_yields` in its last section handle any hypothesis |
| Why don't the old numbers match the reference engine exactly? | The old code used QuTiP's default solver tolerances, which leave about 3e-5 of error in the static yield (checked against exact diagonalisation). The reference engine uses tight tolerances (`SOLVER_OPTIONS`) so it can check the fast engine to about 1e-6 |
| Where is the check that k_S = k_T gives the old yield? | `test_equal_rates_reproduce_reference_engine_static_yield` in `tests/test_model.py` |
